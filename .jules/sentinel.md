## 2024-05-20 - Missing Authorization in Razorpay Edge Function
**Vulnerability:** The `razorpay` Edge Function (`supabase/functions/razorpay/index.ts`) allows any unauthenticated user to call the `release_payment` action and release funds from escrow.
**Learning:** Edge Functions invoked via `supabase.functions.invoke()` need explicit authentication checks (e.g., parsing the JWT token from the `Authorization` header) when performing sensitive operations like transferring funds. Simply using `SUPABASE_SERVICE_ROLE_KEY` bypasses RLS and assumes the backend has verified the request.
**Prevention:** Always verify the caller's JWT token (using `createClient` with `SUPABASE_ANON_KEY` and `auth.getUser(token)`) and ensure they are authorized to perform the action (e.g., verifying they are the owner of the project) before executing sensitive business logic in Edge Functions.
## 2025-02-27 - Supabase Edge Function Missing JWT Validation & IDOR
**Vulnerability:** The `send-notification` Edge Function accepted requests with no Authorization header or invalid tokens, allowing unauthenticated users to trigger notification endpoints and impersonate other users (IDOR) by manually supplying an arbitrary `user_id` when firing `message` events.
**Learning:** `supabase.functions.invoke()` correctly attaches the frontend user's JWT token, but Edge Functions with `verify_jwt = false` in `config.toml` do not enforce it at the gateway. Thus, developers must manually extract the JWT, construct a client with `SUPABASE_ANON_KEY`, call `getUser(token)`, and explicitly authorize the `user_id` payload.
**Prevention:** For any sensitive operation or identity-bound action in Edge Functions, ensure `authHeader` is parsed, `supabaseClient.auth.getUser(token)` is verified, and the `user.id` rigidly matches the affected entity in the payload. Exempt system webhook calls by explicitly checking for `Bearer ${SUPABASE_SERVICE_ROLE_KEY}`.
