## 2024-05-20 - Missing Authorization in Razorpay Edge Function
**Vulnerability:** The `razorpay` Edge Function (`supabase/functions/razorpay/index.ts`) allows any unauthenticated user to call the `release_payment` action and release funds from escrow.
**Learning:** Edge Functions invoked via `supabase.functions.invoke()` need explicit authentication checks (e.g., parsing the JWT token from the `Authorization` header) when performing sensitive operations like transferring funds. Simply using `SUPABASE_SERVICE_ROLE_KEY` bypasses RLS and assumes the backend has verified the request.
**Prevention:** Always verify the caller's JWT token (using `createClient` with `SUPABASE_ANON_KEY` and `auth.getUser(token)`) and ensure they are authorized to perform the action (e.g., verifying they are the owner of the project) before executing sensitive business logic in Edge Functions.

## 2024-05-20 - Missing Authorization in Send-Notification Edge Function
**Vulnerability:** The `send-notification` Edge Function allows any unauthenticated user to trigger arbitrary push and email notifications, including impersonating senders for messages by spoofing the `user_id` payload.
**Learning:** Functions that rely solely on `SUPABASE_SERVICE_ROLE_KEY` bypass all RLS and authentication out-of-the-box. When creating Edge Functions that execute sensitive operations like push notifications or direct messaging on behalf of a user, the caller's JWT token must be verified using `supabase.auth.getUser()`, and the request payload must be explicitly validated against the authenticated user's ID.
**Prevention:** Always extract the JWT from the `Authorization` header, verify it with `SUPABASE_ANON_KEY`, and cross-check the authenticated `user.id` against the payload (e.g., sender `user_id`) to enforce proper authorization boundaries before invoking admin privileges.
