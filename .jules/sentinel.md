## 2024-05-20 - Missing Authorization in Razorpay Edge Function
**Vulnerability:** The `razorpay` Edge Function (`supabase/functions/razorpay/index.ts`) allows any unauthenticated user to call the `release_payment` action and release funds from escrow.
**Learning:** Edge Functions invoked via `supabase.functions.invoke()` need explicit authentication checks (e.g., parsing the JWT token from the `Authorization` header) when performing sensitive operations like transferring funds. Simply using `SUPABASE_SERVICE_ROLE_KEY` bypasses RLS and assumes the backend has verified the request.
**Prevention:** Always verify the caller's JWT token (using `createClient` with `SUPABASE_ANON_KEY` and `auth.getUser(token)`) and ensure they are authorized to perform the action (e.g., verifying they are the owner of the project) before executing sensitive business logic in Edge Functions.

## 2024-05-21 - Missing Authentication in Send Notification Edge Function
**Vulnerability:** The `send-notification` Edge Function did not validate the `Authorization` header, meaning any external user could call the endpoint and trigger emails or push notifications simply by providing valid parameters.
**Learning:** Edge Functions configured with `verify_jwt = false` in `supabase/config.toml` do not automatically validate JWTs. Functions relying on this for backend integrations must implement manual authentication checks to differentiate between valid service_role invocations (like Database Webhooks) and direct, unauthenticated client requests.
**Prevention:** Always parse and validate the JWT from the `Authorization` header inside the function body (`supabase.auth.getUser()`), while explicitly permitting the `SUPABASE_SERVICE_ROLE_KEY` to bypass this check if the function is expected to be invoked via automated backend processes.
