## 2024-05-20 - Missing Authorization in Razorpay Edge Function
**Vulnerability:** The `razorpay` Edge Function (`supabase/functions/razorpay/index.ts`) allows any unauthenticated user to call the `release_payment` action and release funds from escrow.
**Learning:** Edge Functions invoked via `supabase.functions.invoke()` need explicit authentication checks (e.g., parsing the JWT token from the `Authorization` header) when performing sensitive operations like transferring funds. Simply using `SUPABASE_SERVICE_ROLE_KEY` bypasses RLS and assumes the backend has verified the request.
**Prevention:** Always verify the caller's JWT token (using `createClient` with `SUPABASE_ANON_KEY` and `auth.getUser(token)`) and ensure they are authorized to perform the action (e.g., verifying they are the owner of the project) before executing sensitive business logic in Edge Functions.

## 2024-05-21 - Missing Authorization in Send-Notification Edge Function
**Vulnerability:** The `send-notification` Edge Function (`supabase/functions/send-notification/index.ts`) used `SUPABASE_SERVICE_ROLE_KEY` to query the database, but failed to validate the caller's JWT token. This permitted any unauthenticated user to invoke the function or an authenticated user to forge messages as another user. For instance, the `event="message"` payload used an arbitrary `user_id` parameter to determine the sender.
**Learning:** Like other edge functions, authentication must be explicitly validated for `send-notification` using `supabase.auth.getUser(token)`. Furthermore, any ID or parameter indicating the "sender" must be verified against the authenticated user's ID (`authUserId !== user_id`) to prevent impersonation or IDOR.
**Prevention:** Edge Functions that use service role keys must extract and validate the JWT from the `Authorization` header and restrict operations based on the authenticated user's privileges. Allow webhook invocations by explicitly checking if the token is `SUPABASE_SERVICE_ROLE_KEY`.
