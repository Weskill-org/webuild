## 2024-05-20 - Missing Authorization in Razorpay Edge Function
**Vulnerability:** The `razorpay` Edge Function (`supabase/functions/razorpay/index.ts`) allows any unauthenticated user to call the `release_payment` action and release funds from escrow.
**Learning:** Edge Functions invoked via `supabase.functions.invoke()` need explicit authentication checks (e.g., parsing the JWT token from the `Authorization` header) when performing sensitive operations like transferring funds. Simply using `SUPABASE_SERVICE_ROLE_KEY` bypasses RLS and assumes the backend has verified the request.
**Prevention:** Always verify the caller's JWT token (using `createClient` with `SUPABASE_ANON_KEY` and `auth.getUser(token)`) and ensure they are authorized to perform the action (e.g., verifying they are the owner of the project) before executing sensitive business logic in Edge Functions.

## 2024-07-01 - Impersonation in Edge Function
**Vulnerability:** The `send-notification` edge function didn't verify the caller's identity when the `verify_jwt = false` configuration was applied, allowing any client to invoke notifications with arbitrary payloads (including impersonating message senders by passing another `user_id` in the `message` event).
**Learning:** Edge functions that disable automatic JWT verification (`verify_jwt = false`) must manually validate the `Authorization` header and ensure the provided JWT corresponds to the `user_id` inside the request body for sensitive actions like sending messages on behalf of a user. Furthermore, an exemption is needed for backend webhooks that use the service role key.
**Prevention:** Always validate `req.headers.get('Authorization')` manually in `verify_jwt = false` functions using `supabase.auth.getUser()`, and explicitly assert that the authenticated user matches the actor ID in the payload.
