## 2024-05-20 - Missing Authorization in Razorpay Edge Function
**Vulnerability:** The `razorpay` Edge Function (`supabase/functions/razorpay/index.ts`) allows any unauthenticated user to call the `release_payment` action and release funds from escrow.
**Learning:** Edge Functions invoked via `supabase.functions.invoke()` need explicit authentication checks (e.g., parsing the JWT token from the `Authorization` header) when performing sensitive operations like transferring funds. Simply using `SUPABASE_SERVICE_ROLE_KEY` bypasses RLS and assumes the backend has verified the request.
**Prevention:** Always verify the caller's JWT token (using `createClient` with `SUPABASE_ANON_KEY` and `auth.getUser(token)`) and ensure they are authorized to perform the action (e.g., verifying they are the owner of the project) before executing sensitive business logic in Edge Functions.
## 2025-02-27 - Missing Authentication and Impersonation in Send Notification Edge Function
**Vulnerability:** The `send-notification` Edge Function (`supabase/functions/send-notification/index.ts`) lacked authentication, allowing any unauthenticated user to send push notifications and emails. Furthermore, for the `message` event, the function did not validate that the `user_id` parameter (the sender) matched the caller, allowing malicious users to impersonate others and send forged messages.
**Learning:** Edge Functions that process user-submitted actions must explicitly parse the `Authorization` header and verify the caller's JWT token using `supabase.auth.getUser()`. Furthermore, it's critical to strictly validate that payload parameters like `user_id` match the authenticated user's ID to prevent IDOR and impersonation attacks.
**Prevention:** Always verify the caller's JWT in Edge Functions that perform actions on behalf of a user. For functions accepting a `user_id` or similar actor identifier, add a strict equality check (`authUser.id === user_id`) to ensure users can only perform actions for themselves.
