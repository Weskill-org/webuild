## 2024-05-20 - Missing Authorization in Razorpay Edge Function
**Vulnerability:** The `razorpay` Edge Function (`supabase/functions/razorpay/index.ts`) allows any unauthenticated user to call the `release_payment` action and release funds from escrow.
**Learning:** Edge Functions invoked via `supabase.functions.invoke()` need explicit authentication checks (e.g., parsing the JWT token from the `Authorization` header) when performing sensitive operations like transferring funds. Simply using `SUPABASE_SERVICE_ROLE_KEY` bypasses RLS and assumes the backend has verified the request.
**Prevention:** Always verify the caller's JWT token (using `createClient` with `SUPABASE_ANON_KEY` and `auth.getUser(token)`) and ensure they are authorized to perform the action (e.g., verifying they are the owner of the project) before executing sensitive business logic in Edge Functions.
## 2026-07-03 - Unauthenticated Edge Function Allowing Impersonation
**Vulnerability:** The `send-notification` Supabase Edge Function lacked authorization checks, allowing unauthenticated users to trigger notifications and bypass IDOR checks for the `message` event.
**Learning:** Supabase Edge Functions called directly from the frontend via `supabase.functions.invoke()` do pass the authenticated user's JWT in the `Authorization` header, but backend Edge Functions must still explicitly verify it using `supabase.auth.getUser()` when creating a client instance. Relying solely on the `SUPABASE_SERVICE_ROLE_KEY` bypasses RLS and allows spoofing.
**Prevention:** Always verify the caller's JWT using `supabase.auth.getUser()` inside Edge Functions for sensitive actions unless it's a confirmed service role backend invocation. Explicitly validate payload IDs against the authenticated user's ID to prevent IDOR.
