## 2024-05-20 - Missing Authorization in Razorpay Edge Function
**Vulnerability:** The `razorpay` Edge Function (`supabase/functions/razorpay/index.ts`) allows any unauthenticated user to call the `release_payment` action and release funds from escrow.
**Learning:** Edge Functions invoked via `supabase.functions.invoke()` need explicit authentication checks (e.g., parsing the JWT token from the `Authorization` header) when performing sensitive operations like transferring funds. Simply using `SUPABASE_SERVICE_ROLE_KEY` bypasses RLS and assumes the backend has verified the request.
**Prevention:** Always verify the caller's JWT token (using `createClient` with `SUPABASE_ANON_KEY` and `auth.getUser(token)`) and ensure they are authorized to perform the action (e.g., verifying they are the owner of the project) before executing sensitive business logic in Edge Functions.
## 2024-05-20 - Missing Authentication in Send Notification Edge Function
**Vulnerability:** The `send-notification` Edge Function (`supabase/functions/send-notification/index.ts`) allowed any unauthenticated user to trigger push notifications and emails because it directly used the `SUPABASE_SERVICE_ROLE_KEY` without verifying the caller.
**Learning:** Edge Functions invoked directly from the frontend via `supabase.functions.invoke()` must always parse and verify the user's JWT from the `Authorization` header when performing restricted actions like triggering notifications. Using the service role key alone bypasses RLS and assumes the backend has verified the request.
**Prevention:** Always verify the caller's JWT token (using `createClient` with `SUPABASE_ANON_KEY` and `auth.getUser()`) before performing restricted or sensitive logic, particularly around messaging, payments, or actions that can be abused for spam.
